# Дух Свободы App — перенос возможностей Discord-бота

## Принципы

- Discord-бот в Pterodactyl остаётся доверенным исполнителем действий и владельцем основной SQLite.
- Vercel — интерфейс, Discord OAuth2/Activity и защищённая очередь запросов. Браузер никогда не получает Discord Bot Token, SPIRIT_SYNC_SECRET, прямой доступ к SQLite или административные права сам по себе.
- Каждый запрос проверяется по удостоверенному Discord user ID, guild ID, правам и актуальному состоянию. Изменения экономики должны выполняться транзакционно в боте, а не напрямую из браузера/кеша.
- Публичные GET и приватные мутации проектируются отдельно. Записи действий имеют idempotency key, время жизни, журнал аудита и явные состояния (pending/complete/rejected/expired). Доступ администратора проверяется в момент исполнения, а не только при отображении кнопки.
- Сначала подтверждаем путь чтения: Discord OAuth -> Vercel request -> Pterodactyl poll -> Vercel result -> страница пользователя.

## Этапы

1. **Наблюдаемая синхронизация:** подтверждённый лог HTTP 200 при чтении очереди, обновлённые профили; проверка состояния в Activity и на сайте. Не объявлять интеграцию исправной по одному факту запуска модуля.
2. **Профиль и статистика:** XP, уровни, ранг, активность, баланс; только свои данные, безопасная обработка отсутствующих записей.
3. **Достижения и коллекция:** значки, инвентарь, надетые предметы, прогресс достижений, поиск и фильтры.
4. **Магазин и экономика:** витрина, история, затем покупки и экипировка через защищённые команды в боте с перепроверкой баланса и прав.
5. **Ежедневные задания и промокоды:** просмотр, затем безопасная активация и получение наград без повторного списания/начисления.
6. **Обмены и подарки:** предложения и подтверждения с правами обеих сторон; запрет повторных исполнений.
7. **Лидерборд и активности:** отображение актуальных публичных рейтингов и статусов по разрешённым данным.
8. **Администрирование:** конфигурация сервера, модерация, заявки/репорты, аудит и иерархия прав только через серверную авторизацию. Перед каждой мутацией — проверка Discord-ролей, полномочий бота и иерархии.
9. **Minecraft и интеграции:** только безопасные статусы регистрации/проверки и отдельная авторизация для действий; секреты инфраструктуры не выводятся.
10. **Production:** интеграционные тесты, ограничения частоты, диагностика, миграции/резервные копии, отзыв авторизации, мониторинг ошибок.

## Критерии готовности каждого этапа

- Реальный сценарий проверен из Discord и из веб-интерфейса.
- Не существует обхода прав через подмену userId/guildId или повтор запроса.
- Нет прямых записей в SQLite с Vercel; операции исполняет Discord-бот.
- При недоступности Neon/Vercel Discord-команды остаются работоспособными.
- CI зелёный, лог не раскрывает токены, приватные профили или персональные записи.

## Мониторинг текущей синхронизации

После запуска новой версии ожидается лог `Spirit outbound sync connected: jobs endpoint HTTP 200, pending=N.` при первом успешном GET очереди и не чаще раза в час далее. После успешной отправки запрошенного профиля выводится `Spirit outbound sync completed N profile update(s).`

Один успешный GET без задач подтверждает только подключение, **не** доставку профиля. Для полной проверки войдите через Discord на веб-сайт/Activity, откройте свой профиль и убедитесь, что статус изменился с ожидания на активную синхронизацию и реальные данные совпадают с командами бота.

Сетевые IP из диагностики Vercel являются временными предпочтительными адресами. При изменении маршрутизации можно переопределить `SPIRIT_SYNC_PREFERRED_IPV4` на Pterodactyl; пустое значение возвращает обычный DNS. Не отключайте проверку сертификатов.
