# Дух Свободы App

Отдельный Vite-фронтенд с серверными Vercel Functions для входа через Discord. Ветка `feature/spirit-freedom-app` развёрнута на Vercel отдельно от бота.

## Текущий статус
- Главная страница, адаптивная навигация, вкладки профиля и наград.
- Discord OAuth2 `identify`: авторизация, проверка state, серверный обмен code, шифрованная HttpOnly Secure SameSite=Lax сессия, выход.
- `GET /api/me` возвращает только проверенный Discord identity владельца сессии.
- **XP, баланс, награды пока не синхронизированы с Discord-ботом.** Не показываем вымышленные данные.
- В `/admin` бота появилась функция выбора текстового канала и публикации ссылки, которую берёт из `SPIRIT_APP_URL`.

## Что требуется от владельца Discord-приложения
1. В Discord Developer Portal откройте **существующее приложение того же бота**, раздел OAuth2 → Redirects.
2. Зарегистрируйте callback (строго с HTTPS): `https://duh-svobody-app.vercel.app/api/auth/callback`.
3. В Vercel Project → Settings → Environment Variables задайте:
   - `DISCORD_CLIENT_ID`: Application ID того же Discord-приложения.
   - `DISCORD_CLIENT_SECRET`: OAuth2 Client Secret (**секрет**, только Vercel Server Environment, никогда не коммитить).
   - `DISCORD_REDIRECT_URI`: `https://duh-svobody-app.vercel.app/api/auth/callback`.
   - `SESSION_SECRET`: криптографически случайная секретная строка от 32 символов; хранить только в Vercel, не копировать в чат и репозиторий.
4. Назначьте переменные для Production; для Preview используйте отдельный зарегистрированный Redirect URI, если необходима авторизация на Preview.
5. Запустите Redeploy проекта, затем проверьте вход на `https://duh-svobody-app.vercel.app`.
6. Для бота в Pterodactyl добавьте `SPIRIT_APP_URL=https://duh-svobody-app.vercel.app`, затем перезапустите бота; вызовите `/admin` → Spirit App.

Токен самого бота `DISCORD_TOKEN` в Vercel **не добавляйте**. В продакшене API требует однозначный `DISCORD_REDIRECT_URI`. Состояние входа действительно 10 минут, сессия — 12 часов. Функции бота и его база остаются на сервере бота.

## Локальная разработка
```bash
cd app
npm install
npm run check
npm run test
npm run dev
npm run build
```

Локальный OAuth требует отдельной конфигурации HTTPS и отдельно разрешённого Discord redirect; нельзя перенаправлять авторизацию на произвольный домен. 

## Архитектурный следующий шаг
Безопасная синхронизация `guild_id + user_id` через серверный API, с аутентификацией между Vercel и сервером бота. Нельзя подключать браузер напрямую к SQLite или отдавать пользователю чужие записи. Текущая кнопка публикации открывает сайт, **не Discord Activity**.

## Синхронизация реального профиля (опциональная серверная интеграция)

Реальные XP, уровень, баланс и выданные достижения доступны через **отдельный серверный HTTPS-запрос** к боту. В браузер попадают только данные вошедшего участника, не SQLite, токены или общий список пользователей.

Бот (Pterodactyl, переменные окружения):
- `SPIRIT_PROFILE_API_TOKEN` — отдельный случайный ключ **минимум 32 байта**, отличающийся от токена Discord и остальных ключей.
- `SPIRIT_PROFILE_API_HOST` — по умолчанию `127.0.0.1`; рекомендуется оставлять на loopback и публиковать через доверенный HTTPS reverse proxy.
- `SPIRIT_PROFILE_API_PORT` — по умолчанию `3071`. Проверьте выделение порта и доступность прокси. Нельзя просто открыть этот порт на общий интернет без ограничения входящего доступа.

Vercel (только Production, серверные переменные):
- `SPIRIT_PROFILE_API_URL` — публичный HTTPS-origin доверенного proxy, например `https://profile-api.example.org` (без дополнительного пути и query).
- `SPIRIT_PROFILE_API_SECRET` — **тот же самый** ключ, что `SPIRIT_PROFILE_API_TOKEN` у бота.

Запрос: `GET /api/v1/spirit/profile?userId=<Discord ID>`. Vercel подписывает HMAC-SHA256 дату, nonce, метод и путь с query. Бот отклоняет неподписанные, устаревшие и изменённые запросы; доступ к базе только для чтения, ограниченный заданным `GUILD_ID`. При недоступности backend сайт продолжает работать с Discord identity, а статистика остаётся скрытой.

**Не включайте** серверный API, пока нет HTTPS reverse proxy и подходящей сетевой конфигурации. Отсутствие `SPIRIT_PROFILE_API_TOKEN` штатно отключает слушатель. Профильное API не должно использовать секрет OAuth2, Bot Token или Minecraft API Token.

Для технического тестирования: `npm run check && npm test` в `app/`; `node scripts/test-spirit-profile-api.js` в корне.

## Расширенная синхронизация (бета)

После подключения защищённого серверного API и входа через Discord доступны только **личные данные** авторизованного участника из существующей базы бота:
- XP, уровень, баланс, текущий ранг и статистика активности.
- Полученные достижения, инвентарь и надетые косметические предметы.
- Каталог магазина (просмотр), текущий прогресс ежедневных заданий.
- История **собственных уже использованных** промокодов; активные неиспользованные секретные коды администратора не раскрываются.
- Последние личные операции с монетами (без игровых ставок).

Сайт пока **не выполняет** покупку, обмен, выдачу призов или активацию промокодов: для этого используются существующие команды `/shop`, `/promo` и другие команды Discord-бота. Это позволяет проверять синхронизацию без изменения экономических транзакций в веб-приложении.

При отсутствии `SPIRIT_PROFILE_API_URL`, `SPIRIT_PROFILE_API_SECRET` или работающего HTTPS reverse proxy реальный профиль не загружается; пользователь видит Discord identity и честное сообщение о недоступности синхронизации. **Запуск бота без SPIRIT_PROFILE_API_TOKEN не открывает дополнительный порт**. Не публикуйте его HTTP-порт напрямую и не передавайте токен в чат.

Обновление сайта появляется в Production после merge в `main`; действующий Discord-бот в Pterodactyl необходимо отдельно обновить из `main` и перезапустить.
