# Дух Свободы App — интеграция Discord-бота

## Цель
Развивать `app/` как единый интерфейс управления функциями бота без второй независимой экономики или обхода Discord-прав. Перенос означает запуск действий через авторизованный backend, а не перенос токена, SQLite или административных полномочий в браузер.

## Текущий статус (18.11.2026)
- Pterodactyl: Discord, SQLite, 30 slash-команд и Herade Security API запускаются.
- Vercel Production: `SPIRIT_SYNC_SECRET` и `SPIRIT_SYNC_DATABASE_URL` присутствуют; значения не публикуются.
- В коде реализованы `GET /api/sync/jobs`, `POST /api/sync/result` и `GET /api/me`, который показывает статус `pending` или `connected`.
- Бот регистрирует `Spirit outbound sync connected: jobs endpoint HTTP 200` при успешном опросе и `Spirit outbound sync completed N profile update(s)` после успешного заполнения очереди.
- **Успешный реальный обмен на Pterodactyl пока не подтверждён отдельным логом после последнего обновления.**
- Для домена `duh-svobody-app.vercel.app` сервер Pterodactyl успешно проверил два IPv4-адреса Vercel; теперь бот пробует их прежде DNS и сохраняет проверку TLS.
- `SPIRIT_PROFILE_API_TOKEN` не требуется для режима исходящей синхронизации; его отсутствие не является ошибкой.

## Проверка готовности — строго по этапам
1. Перезапустить бот с актуальной веткой `main`. Ожидать `Spirit outbound sync connected: jobs endpoint HTTP 200, pending=...`. Если приходит HTTP 401, проверить одинаковый `SPIRIT_SYNC_SECRET` у обеих сторон без вывода его в логи.
2. Открыть `https://duh-svobody-app.vercel.app`, войти через Discord и выбрать свой профиль. `GET /api/me` должен отдать `sync: pending`, пока бот не обработал запрос.
3. Дождаться сообщения `Spirit outbound sync completed 1 profile update(s)` или более. Убедиться, что в приложении появились **реальные** XP, уровень и баланс того же Discord user ID, а `sync` перешёл в `connected`.
4. Проверить, что другой пользователь не может получить чужой профиль через `/api/me`, а `/api/sync/jobs` и `/api/sync/result` без секрета возвращают HTTP 401.
5. Проверить повторное обновление после устаревания кэша (120 секунд), а также работу интерфейса при временном отключении сети.
6. До выполнения всех шагов не объявлять интеграцию end-to-end проверенной. Не публиковать в отчётах реальные токены, строки подключения и персональные данные.

## Принципы расширения функций
- **Источник истины:** SQLite бота и существующие сервисы экономики/модерации. Neon хранит только очередь и разрешённые снимки, не отдельные независимые балансы.
- **Личность:** Discord OAuth2 или проверенная Discord Activity-сессия; каждый запрос пользователя ограничен его `user_id` и нужным `guild_id`.
- **Действия:** для покупок, переводов и административных операций позже нужен отдельный подтверждаемый защищённый job/action канал на стороне бота, с idempotency keys, сроком действия, явной проверкой прав в боте и журналом аудита.
- **Никаких прямых мутаций SQLite из Vercel**, токенов Discord и секретных ключей во фронтенде.
- **Согласованность:** вся экономика меняется только в транзакциях бота; у каждой операции есть подтверждённый результат, серверные лимиты и защита от повторов.
- **Отказоустойчивость:** отключение Vercel не должно останавливать Discord-бота, а offline-статус сайта не должен выдавать недостоверные данные за актуальные.

## Очередность внедрения
1. **Связь и профиль:** подтверждённый end-to-end sync, мониторинг ошибок, статус свежести данных, XP, уровни, ранг, голосовая активность.
2. **Достижения и коллекции:** значки, инвентарь, экипировка, титулы и оформление; сначала только чтение, затем безопасные изменения.
3. **Магазин и экономика:** каталог, баланс, покупки, подарки, торговля, переводы; транзакции только через backend бота и аудит.
4. **Задания, промокоды и события:** прогресс и история, безопасная активация без раскрытия действующих кодов.
5. **Рейтинги и социальные разделы:** лидерборды и статистика с разрешённой публичной видимостью.
6. **Модерация и администрация:** жалобы, настройки сервера, роли, панели персонала, действия по правам Discord на момент каждой операции; журналирование.
7. **Остальные команды:** перенос после инвентаризации текущих команд и тестов равенства поведения Discord и App.

## Release gate каждого раздела
- Тесты доступа, прав, ограничений и повторных вызовов.
- Подтверждение отсутствия раскрытия чужих данных и ключей.
- GitHub CI зелёный; проверки на тестовом сервере Discord и Production Vercel.
- Отдельный откат, не затрагивающий SQLite; статус «готово» только после проверки живой функции.
